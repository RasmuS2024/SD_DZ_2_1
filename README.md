## О проекте
Консольное приложение для учета личных финансов. Позволяет вести счета, категории доходов/расходов и операции.

## Предметная область
Программа моделирует три основные сущности:
- **Счет** - хранилище средств с уникальным ID, названием и балансом
- **Категория** - группировка операций по типу (доход/расход) с названием
- **Операция** - движение средств с привязкой к счету, категории, суммой, датой и описанием

## Архитектура и SOLID

**Single Responsibility**
- Модели (BankAccount, Category, Operation) - только данные
- Репозитории - только хранение и поиск
- Сервисы - только бизнес-логика
- Хелперы - только консольный ввод/вывод

**Open/Closed**
- Сервисы работают через интерфейсы (AccountService, CategoryService, OperationService)
- Можно добавить новую реализацию (например, другой способ хранения) без изменения кода

**Liskov Substitution**
- Отсутствует наследование, принцип соблюдается автоматически

**Interface Segregation**
- Узкие интерфейсы сервисов, каждый отвечает за свою область
- Нет "жирных" интерфейсов с неиспользуемыми методами

**Dependency Inversion**
- Зависимости направлены на абстракции (интерфейсы), а не на конкретные классы
- Внедрение зависимостей через конструктор (DI)

## DI-контейнер
Используется Spring Framework:
- `@Service` - для сервисов
- `@Repository` - для репозиториев
- `@Component` - для вспомогательных классов
- `@Autowired` - для внедрения зависимостей

## Проблемы при расширении
1. **Добавление новых типов счетов** (кредитный, дебетовый) - потребует изменения логики в AccountService и OperationService
2. **Смена способа хранения данных** (БД вместо памяти) - потребуется менять все репозитории
3. **Добавление валют** - изменения в BankAccount и всех сервисах, работающих с балансом
4. **Сложные отчеты** - текущая архитектура не оптимизирована для аналитики

## Почему абстракции улучшили дизайн
1. **Разделение ответственности** - каждый класс делает только свою работу
2. **Тестируемость** - легко писать модульные тесты с моками
3. **Гибкость** - можно менять реализацию не затрагивая другие модули
4. **Читаемость** - понятная структура, легко найти нужный код
5. **Поддержка** - изолированные изменения, меньше побочных эффектов
